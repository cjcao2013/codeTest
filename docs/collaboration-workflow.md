# 与 Claude Code 的协作方式记录

本文记录了在 TAP Migration Demo 前端开发中，用户与 Claude Code 的实际交互方式，供未来参考复用。

---

## 整体流程

```
想法 → 头脑风暴 → 设计文档 → 实现计划 → 分 Agent 执行 → 文档更新
```

这套流程由 Claude Code 的 `/superpowers:brainstorming` + `writing-plans` + `subagent-driven-development` 技能驱动，用户只需在关键节点做决策。

---

## 用户的交互风格

### 1. 授权决策，不纠结细节

用户多次直接说"**你帮我决定就可以**"，不在方案选择上花时间。例如：

- 技术栈选型（React vs Vue、SSE vs WebSocket）→ 让 Claude 推荐
- 是否要可视化 companion → "你决定就好"
- 每个设计 section 是否通过 → "你决定"

**适用场景：** 当你对某个选择没有强烈偏好，或者不熟悉技术细节时，直接授权可以大幅提速。

### 2. 批量委托审核

用户不参与每轮代码审查，而是说"**你帮我审核就可以**"，把 spec review 和 code quality review 全部交给 Claude。

**背后机制：** Claude 在每个任务后自动派出两个审查 subagent（spec compliance → code quality），发现问题则让实现 subagent 修复，审核通过才推进下一个任务。用户只看最终结果。

### 3. 追加需求，自然插入

用户在执行过程中用对话直接补充需求，无需重启流程：

- "完成之后，把相关的文档也更新噢" → 任务完成后自动补跑文档更新
- "如果有审核，你帮我看就可以" → Claude 调整后续所有任务的审核策略

**关键点：** 这类需求在 Claude 完成当前子任务后会被自动处理（系统提示会保留这些 pending 消息）。

### 4. 简短指令触发完整工作流

用户的单条消息往往很短，但触发了大量工作：

| 用户输入 | Claude 实际执行 |
|---------|--------------|
| `c`（选 C 方案） | 进入设计呈现阶段 |
| `你帮我决定` | Claude 选定方案 A 并直接推进 |
| `1`（选 subagent 驱动） | 派出 16 个实现 subagent + 32 个审查 subagent |
| `继续` | 从额度重置后断点恢复，继续执行 Task 8 |

---

## 头脑风暴阶段（/superpowers:brainstorming）

**触发方式：** 直接描述项目背景和问题

> "这个项目用于迁移演示的 demo，但是现在只有后端吧？"

**Claude 的步骤：**
1. 探索项目现状（读代码、看 git log）
2. 每次只问一个问题，逐步确认需求
3. 提出 2-3 个方案，给出推荐理由
4. 呈现完整设计（分 section，每节确认）
5. 写入 spec 文档，自动跑审查循环

**用户需要做的：** 回答 4 个选择题（A/B/C/D 或简短描述），其余交给 Claude。

---

## 计划阶段（writing-plans）

头脑风暴结束后自动进入，无需用户额外操作。

Claude 输出的计划包含：
- 每个任务的完整代码（可直接执行）
- TDD 步骤（写测试 → 跑失败 → 实现 → 跑通过 → commit）
- 精确的文件路径和 bash 命令
- 预期输出（如"Expected: 4 passed"）

计划写完后会自动跑一个 plan reviewer subagent，发现问题则修复再审，最多 3 轮。

---

## 执行阶段（subagent-driven-development）

**触发方式：** 用户输入 `1`（选择 subagent 驱动方式）

**每个任务的执行流程：**

```
派实现 subagent → 实现 + 自测 + commit
    ↓
派 spec reviewer → 确认代码符合规格
    ↓（不符合则让实现 subagent 修复）
派 code quality reviewer → 确认代码质量
    ↓（有问题则修复）
标记任务完成，推进下一个
```

**用户感知：** 看到任务列表逐个变绿，偶尔看到某个任务在修复 issue。不需要介入。

---

## 遇到限制时的处理

用户遇到了一次 Claude API 额度限制：

```
You've hit your limit · resets 11am (Asia/Shanghai)
```

恢复后用户发送"继续"，Claude 从断点（Task 8）重新开始，不需要重新说明背景。

**原因：** Claude 的 task list 和 session 上下文保留了执行状态，"继续"足以恢复。

---

## 文档更新

用户在执行中途提出："**完成之后，把相关的文档也更新噢**"

Claude 在所有 16 个任务完成后，自动：
1. 读取现有 README
2. 新增 Web Demo 章节（架构表、Quick Start、测试命令）
3. 更新目录表格
4. commit

用户无需提供任何额外信息。

---

## 可复用的交互模式

如果你想在其他项目里用同样的方式协作：

```
1. 描述现状和想做什么（一两句话即可）
   → 触发 /superpowers:brainstorming

2. 回答 3-5 个选择题，其余说"你决定"

3. 看 Claude 呈现设计，说"你帮我审核"或直接确认

4. 计划完成后输入 1（subagent 驱动）

5. 等待执行完成，期间可以随时追加需求

6. 结束前说"更新文档" → 自动补全
```

**最省力的版本：** 每一步都说"你帮我决定"——Claude 会做出合理选择并解释原因，你在结果上确认即可。
